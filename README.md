# Webmunk Shopping Study — side-panel update (2.0.3)

Download this repository using **Code → Download ZIP**, extract it, and start with LOCAL_TESTING.md. The included **local-preview/** folder is ready to load unpacked in Chrome. It is a test build, not a participant/release package.

## Changes

Version 2.0.3 fixes classic-arm assistant suppression found broken during a live-Chrome retest on real Amazon: Amazon docks Rufus by adding classes and inline padding to `<body>` itself, which the suppression logic never touched, and the live trigger button (`#nav-rufus-disco`) wasn't in the selector list. See UX_REVIEW.md's incident section for the root cause and fix. No permission or manifest surface changes beyond the version bump.

Version 2.0.2 explicitly names the Alexa AI shopping assistant in the guided-chat reminder. After P2 opens, the extension closes its side panel on browsers exposing `sidePanel.close()` (Chrome 141+). If closing is unavailable or fails, or the panel is reopened, it displays only “Shopping task completed.” Failed P2 navigation preserves the retry interface. No new permissions; minimum Chrome remains 116. The extension stays installed and pending event delivery can continue without new shopping collection.

Version 2.0.1 removes the bottom-left overlay, adds bounded outer-dock suppression, accepts the category phrases in the actual P1 export, delays product-selection controls until a cart snapshot exists, and connects P2. See UX_REVIEW.md.

- Responsive Chrome side panel replaces the popup; minimum Chrome 116. The only added API permission is `sidePanel`.
- An Amazon “Open study panel” button makes the workflow discoverable. First opening requires a click; users can still close the panel.
- Qualtrics retains submission/redirect responsibility. No Next-button control, Qualtrics page injection, `activeTab` or `scripting`. The existing external installation-check ping remains.
- Valid Amazon handoffs auto-register PID, arm and category. Missing assignments do not default to chat. Conflicting and legacy sessions fail closed.
- Classic suppression uses centralized Rufus/Alexa control selectors and reacts to assignment changes. It avoids the former broad selector that could hide ordinary Alexa products. Live Amazon coverage still needs testing.
- Participants select a cart product and explicitly confirm it. The worker re-reads the live cart. A nonempty or pre-existing cart never automatically completes the task.
- Behavioral telemetry requires an enrolled, signed-in shopping session; it stops before the P2 redirect, or on explicit stop. Account/sign-in/checkout paths are excluded.
- P2 receives `PROLIFIC_PID`, `arm`, `category`, `budget`, `session_id`. The respondent URL is in `src/shared/StudyConfig.ts`; `FINAL_SURVEY_URL` can override it at production build time. It no longer selects the last Remote Config survey entry. Preview adds `webmunk_test=1`; real production does not. Qualtrics must explicitly store these embedded fields.
- The panel’s assistant-use prompt appears only in `chat`, not `chat_no_guide`.
- Summary state survives service-worker restart; production event envelopes are queued locally before delivery attempts.
- Assistant capture no longer reads arbitrary page inputs or unsent drafts.

## Build modes

| Folder | Registration/events | Final survey | Use |
| --- | --- | --- | --- |
| `local-preview/` | Mock registration; local events only | Configured P2 with `webmunk_test=1` | UX/condition/cart tests with dummy IDs |
| `production-build/` (not included) | Existing Firebase + Jitsu | Explicit researcher-supplied P2 | End-to-end validation, then review |

Google does not require Firebase/Jitsu. They are this project’s existing choices. Supabase could replace them, but no backend migration is included. `Backend.ts` is the production adapter; the preview substitutes `PreviewBackend.ts`.

The original source export omitted its build system and backend settings. Build scripts and `.env.example` are now included; missing settings have not been fabricated, and nothing has been deployed.

## Developer commands

Node.js 24+ is needed to rebuild/run tests, but NOT just to load the included preview.

```sh
npm run build:preview
npm test
```

Production also needs dependencies and the existing study settings in `.env`:

```sh
npm install
npm run check
npm run build
```

Production intentionally fails without required settings or authorized ingestion hosts. Production dependency installation/type-check/build and live network delivery were not run here. Preserve the lockfile generated by your production installation and test those exact resolved versions.

Never put Firebase service-account keys, Supabase secret/service-role keys, database/admin credentials or private extension signing keys in the extension. Client configuration is visible to participants.

## Measurement and release notes

- `decision_made` still means first add-to-cart click, NOT final choice; `decision_definition` makes that explicit. Use `final_choice_confirmed` for the explicit outcome.
- Summaries now have `summary_scope: study_session` instead of separate tab-close summaries. Production envelopes use `schema_version: 3`. Review downstream transformations before recruitment.
- The backend’s `sessionUid` remains canonical when supplied; otherwise a generated UUID is used consistently.
- `add_click_observed` is evidence, not proof that a cart item was newly added. Baseline counts do not identify pre-existing ASINs. Duplicate matching ASIN rows fail closed.
- Budget/category compliance, variant, shipping/tax/currency and lottery eligibility are not automatically verified. Prices are displayed for participant confirmation. Non-US numeric subtotals may be null rather than guessed.
- Login, assistant and cart detection are DOM-based, not Amazon API guarantees. Unknown or inaccessible shadow-DOM/cross-origin interfaces remain limitations. Recheck selectors before launch.
- While active, shopping pages on the assigned Amazon origin can be logged across tabs. Other marketplaces, excluded account/payment pages, Qualtrics and unrelated sites are not logged as shopping.
- Installation alone does not start behavioral collection. Enrollment emits a registration event; behavior waits for detected sign-in. Previously queued events may still upload after collection stops.
- A one-hour maximum from the initial handoff prevents abandoned sessions from recording indefinitely. This is a safety cap, not the advertised task duration; adjust `SESSION_MAX_MS` deliberately if your protocol needs a different limit.
- Dwell is foreground elapsed time, not proven attention. Device-sleep gaps are not fully modeled; no idle/alarms permissions were added.
- Event retries survive worker suspension but depend on future events/worker wakeups. SDK acceptance is not proof of warehouse delivery. Check actual rows, offline recovery and server-side `event_id` deduplication.
- Completed/stopped sessions do not silently restart. Deploy between cohorts. Old registrations without the new context stop with an error instead of unsafe in-flight migration.
- A global panel remaining visible on another website does not grant page access or enable tracking there.
- Align consent, retention and Store privacy disclosures with the actual fields/window. PID-linked data is not anonymous.

Do not upload this source archive or `local-preview/` to the Store. Package only a configured, end-to-end-tested `production-build/`, with `manifest.json` at the ZIP root. The version/permission change requires an extension update/review. There is no new Qualtrics host permission. No Store submission has been made.
